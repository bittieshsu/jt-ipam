導入流程Adoption roadmap導入ガイド

Each phase has a clear finish line, and you move on only when it is met, so the data can be trusted at every step.jt-ipam を社内に導入するネットワーク管理者と情報システム部門の責任者向けのガイドです。インストールから自動化までを 6 つのフェーズに分け、順番に機能を有効にしていきます。各フェーズには完了の目安があり、それを満たしてから次へ進むので、どの段階でもデータを信頼できます。

為什麼要分階段Why roll out in phases段階的に導入する理由

先有規劃，再讓機器補上事實Plan first, then let machines add the factsまず計画、事実は機械に補わせる

子網路與 IP 的規劃是人決定的「應該如何」；掃描與整合回報的是「實際如何」。先把規劃建好，回報的資料才有東西可以比對，落差才看得出來。The subnet and IP plan is what people decide should be; scans and integrations report what actually is. Build the plan first and the reports have something to be compared against, so the gaps show.サブネットと IP の計画は人が決める「あるべき姿」、スキャンと連携が報告するのは「実際の姿」です。計画を先に作っておけば、報告されたデータと突き合わせて差分が見えるようになります。

先唯讀比對，再考慮自動建立Read-only first, auto-create laterまず読み取りで照合、自動作成は後で

整合一律唯讀拉取。會自動建立 IP 紀錄的開關，除了 LibreNMS 的「自動建立裝置主 IP」之外都預設關閉。先觀察一陣子比對結果，確定來源可靠再開；否則私接的設備會被安靜地收成正式紀錄。Integrations always pull read-only. Every switch that creates IP records is off by default, except LibreNMS's "Auto-create device primary IPs". Watch the comparisons for a while and turn one on only once you trust the source; otherwise an unauthorised device quietly becomes an official record.連携は常に読み取り専用で取得します。IP レコードを自動作成するスイッチは、LibreNMS の「機器の主 IP を自動作成する」を除いてすべて既定で無効です。しばらく照合結果を観察し、ソースを信頼できると判断してから有効にしてください。そうしないと、無断で接続された機器が正式なレコードとして静かに登録されてしまいます。

每個階段都有完成標準Every phase has a finish line各フェーズに完了の目安

總表的「完成標準」達到了再進下一階段。跳過的話，後面的偵測（例如未授權 IP）會因為底下的資料不完整而一直誤報，大家很快就不再相信它。Move on when the "done when" column is met. Skip ahead and later checks (unauthorised IPs, for example) keep raising false alarms because the data underneath is incomplete, and people soon stop trusting them.一覧の「完了の目安」を満たしてから次のフェーズへ進みます。飛ばしてしまうと、後の検知（たとえば未許可の IP）が土台のデータ不足のために誤報を出し続け、すぐに誰も信用しなくなります。

jt-ipam 是集中記錄與管理的工具：它不會發放或回收位址，也不會封鎖設備。實際的發放與阻擋仍由你的 DHCP、防火牆與 NAC 負責。詳見定位說明。jt-ipam records and manages; it does not hand out or revoke addresses, and it does not block devices. Assignment and blocking stay with your DHCP, firewalls and NAC. See what it is.jt-ipam は記録と集中管理のための道具です。アドレスの払い出しや回収、機器の遮断は行いません。それらは引き続き DHCP・ファイアウォール・NAC の役割です。詳しくは位置づけをご覧ください。

常見地雷Common pitfallsよくある落とし穴

  • 還原需要同一把 ENCRYPTION_KEY（在 /etc/jt-ipam/backend.env）才解得開整合帳密等加密欄位。備份檔已包含這個檔案，所以異地備份要當機密保管。A restore needs the same ENCRYPTION_KEY (in /etc/jt-ipam/backend.env) to decrypt integration credentials and other encrypted fields. The backup includes that file, so treat off-site copies as secrets.復元には同じ ENCRYPTION_KEY（/etc/jt-ipam/backend.env 内）が必要で、これがないと連携の認証情報などの暗号化項目を復号できません。バックアップにはこのファイルが含まれるので、外部保管のコピーは機密として扱ってください。
  • 在 jt-ipam 前面再放一層自己的反向代理或負載平衡器時，那一層也要設同一套安全標頭；安全標頭不會自動跨過多出來的那一跳。If you put your own reverse proxy or load balancer in front, it must send the same security headers; they do not survive the extra hop on their own.jt-ipam の前段に独自のリバースプロキシやロードバランサーを置く場合、そこでも同じセキュリティヘッダーを設定してください。ヘッダーは余分な中継を自動では通り抜けません。
  • 主機規格照建議值準備（4 核心、8 GB、50 GB）：稽核記錄、IP 歷程與備份會一直成長。自架 LLM 不要和 jt-ipam 放同一台。Size the host at the recommended 4 vCPU, 8 GB and 50 GB: the audit log, IP history and backups keep growing. Do not run a self-hosted LLM on the same machine.ホストは推奨値（4 コア、8 GB、50 GB）で用意してください。監査ログ、IP の履歴、バックアップは増え続けます。自前の LLM を同じマシンで動かすのは避けてください。

Higher sources depend on the lower data being right.   • 事件規則試跑一次，確認通知真的送得到。Dry-run an event rule and confirm the notification actually arrives.イベントルールを試行し、通知が実際に届くことを確認します。
  • API 權杖都有期限、權限最小，離職或換手時收回。API tokens all have an expiry and minimal rights, and are revoked when people leave or hand over.API トークンにはすべて期限と最小限の権限があり、退職や引き継ぎの際に取り消すこと。

常見地雷Common pitfallsよくある落とし穴

  • 改用外部 OpenAI 相容服務時，子網路、主機名稱與拓樸會送到該服務；資料不能離開公司就維持自架。Switching to an external OpenAI-compatible service sends subnets, hostnames and topology to that provider; keep it self-hosted if the data must not leave.外部の OpenAI 互換サービスに切り替えると、サブネット、ホスト名、トポロジーがその事業者に送られます。データを社外に出せない場合は自前のままにしてください。
  • 嵌入模型的維度要和資料庫欄位一致（預設 768），否則語意搜尋不會報錯，只是永遠找不到東西；換模型後在設定頁按「檢查維度」。The embedding model's dimension must match the database column (768 by default); otherwise semantic search raises no error and simply never finds anything. After changing models, press "Check dimension" on the settings page.埋め込みモデルの次元はデータベースの列と一致させてください（既定 768）。一致しないと意味検索はエラーを出さず、ただ何も見つからなくなります。モデルを変えたら設定ページで「次元を確認」を押してください。
  • 升級或重啟服務會切斷進行中的主控台連線與檔案上傳，請挑維護時段進行。Upgrades and service restarts cut console sessions and file uploads in progress; schedule them in a maintenance window.アップグレードやサービスの再起動は、進行中のコンソール接続とファイルのアップロードを切断します。メンテナンスの時間帯に行ってください。
  • 憑證代理的金鑰等同它範圍內所有憑證的私鑰，要當最高機密保管。A certificate agent's key is as good as the private keys of every certificate in its scope; guard it as a top-tier secret.証明書エージェントのキーは、その範囲内のすべての証明書の秘密鍵に相当します。最高機密として保管してください。
