# 合規對照：ISO/IEC 27001:2022 與 ISO/IEC 42001:2023

> 本檔由 scripts/gen-compliance-docs.py 產生，請改那支腳本再重新產生。

jt-ipam 本身不是一張認證，用了它也不代表通過 ISO/IEC 27001:2022 或 ISO/IEC 42001:2023。這份文件分兩部分：jt-ipam 已經做到、可以拿來當佐證的控制（每一項都附上可以自行驗證的測試或設定位置），以及導入組織使用 jt-ipam 之後要自己負責的事。

這裡只列出目前程式確實具備的功能，依 main 分支撰寫（1.0.5 之後的改動見 CHANGELOG 的 Unreleased），之後的變動以 CHANGELOG 為準。正式盤點時請固定版本或 commit，並在自己的環境實際驗收。

## ISO/IEC 42001:2023：AI 功能與控制

### AI 功能清冊

| AI 功能 | 用途 | 預設 |
|---|---|---|
| AI 對話 | 用自然語言查詢 IPAM，模型透過工具取得資料 | 啟用 LLM 後可用 |
| 語意搜尋 | 以嵌入模型做相似度搜尋 | 啟用 LLM 後可用 |
| IP 調查判讀、IP 研判卡 | 把已查到的事實整理成說明 | 啟用 LLM 後可用 |
| 防火牆規則異動判讀 | 解釋程式比對出的規則差異 | 啟用 LLM 後可用 |
| IP 變更評估的 AI 建議 | 依評估結果提出待辦建議 | 啟用 LLM 後可用 |
| AI 巡檢 | 排程檢視資料並列出發現 | 關閉 |
| 外部 MCP | 讓外部 AI 用戶端呼叫 jt-ipam 的工具 | 關閉 |

模型端點可以是自架的 Ollama，或 OpenAI 相容的 API（由管理員選擇）。LLM 未啟用時，以上功能都不會呼叫模型；AI 巡檢與外部 MCP 另有各自的開關。異常偵測、規則異動偵測與 IP 變更評估的結果由程式查詢算出，不是模型產生的。

## 導入組織要負責的事

### 資訊安全（ISO/IEC 27001:2022）

- 帳號：在使用者管理頁的「登入安全」把雙因素驗證設成管理員必須或所有人必須，並定期確認例外。（A.5.17、A.8.5）
- 離職與調職：停用帳號（工作階段、API 權杖與開著的主控台會一併失效），或用「強制登出」結束所有登入；調整權限與群組成員。（A.5.18、A.6.5）
- 存取審查：定期檢視權限指派、群組成員、API 權杖、主控台授權與登入中的工作階段，必要時對照稽核記錄。（A.5.18、A.8.2）
- 整合帳號：每個整合使用專用的最小權限帳號，多數整合只需要唯讀；定期輪替密碼與金鑰；到期通知出現時及時更換權杖。（A.5.17、A.8.2）
- 金鑰與備份：設定備份加密密碼並把密碼保存在 jt-ipam 主機以外；把備份放到異地儲存，定期做還原演練（含解密），並訂出 RPO 與 RTO。（A.5.30、A.8.13）
- 稽核證據：把稽核記錄轉送到獨立、不可改寫的 Graylog 或 SIEM 儲存，定期查看稽核鏈的驗證結果；還原備份或使用外部資料庫時執行 harden-audit。（A.5.28、A.8.15）
- 網路：只開放必要的連入埠；把 jt-ipam 放在管理網段；Graylog DSV 盡量走 HTTPS，必須用明文 8088 時限制允許的來源位址。（A.8.20、A.8.22）
- 掃描代理與憑證代理：只指派需要的子網路與憑證；不再使用的代理停用或刪除，定期輪替代理金鑰。（A.5.18）
- 更新：追蹤新版本並依 CHANGELOG 升級（升級腳本會先備份）。（A.8.8、A.8.32）
- 管理制度：風險評鑑與處理、適用性聲明、教育訓練、內部稽核與管理審查由導入組織負責。（6.1.2、6.1.3、7.2、7.3、9.2、9.3）

### AI 管理（ISO/IEC 42001:2023）

- AI 政策與清冊：決定要開哪些 AI 功能、由誰負責，記錄模型端點與版本。（5.2、A.2.2、A.3.2、A.4.2）
- 資料流：選擇自架模型或外部 API；若開放外部 MCP，外部 AI 用戶端拿到的資料可能再交給它自己的雲端模型處理，這條資料流要另外評估與核准。（A.10.3）
- 模型變更：換模型或調整參數前，用一組固定問題做回歸測試（工具使用、查詢範圍、查無結果時的回答）。（A.6.2.4、A.6.2.5）
- 人工覆核：AI 的回答與巡檢發現是建議，不是結論；網路變更走 IP 變更評估與審核流程。（A.9.2）
- 影響評估：評估錯誤判讀對人與組織的影響，例如誤把設備歸給某位使用者、錯誤的維護建議造成服務中斷。（6.1.4、8.4、A.5.2、A.5.4）
- 事件處理：訂出回報 AI 錯誤與暫停 AI 功能的程序（LLM 全域開關）。（A.3.3、A.8.4）
- 管理制度：適用性聲明、教育訓練、內部稽核與管理審查由導入組織負責。（6.1.3、7.2、7.3、9.2、9.3）

## 建議的驗收案例

| 驗收案例 | 合格判定 | 驗證方式（測試、設定） |
|---|---|---|
| A、B 單位使用相同的私有網段 | A 透過搜尋、IP 關聯、AI 對話與 MCP 都拿不到 B 的資料 | `test_search_overlapping.py`, `test_mcp_rbac_scope.py` |
| 唯讀權杖或一般帳號要求修改 IP | 後端拒絕，資料沒有變更 | `test_api_token_scope.py`, `test_mcp_admin_tools.py` |
| 查詢結果超過單次上限 | 回傳總數與本次筆數，不把部分清單當成全部 | `test_mcp_tool_scoping.py` |
| 查無資料 | AI 照實說沒有，不編造位址或設備 | `test_ai_no_results_are_explicit.py` |
| 核准後依據改變 | 舊核准不能直接套用，要重新評估 | `test_change_impact_api.py` |
| 撤銷 API 權杖或停用帳號 | 下一個 REST、API 權杖或 MCP 請求就被拒絕 | `test_api_token_scope.py`, `app/api/v1/dependencies.py` |
| 修改或刪除稽核記錄 | 資料庫拒絕；鏈尾錨定能發現尾端被截掉 | `test_audit_immutability.py`, `test_audit_anchor.py` |
| 重複使用主控台票證 | 第二次使用被拒絕 | `test_ticket_take_once.py` |
| 管理員要求所有人使用雙因素驗證 | 沒設定的人登入時先設定並拿到復原碼，不能自行停用；復原碼只能用一次 | `test_mfa_policy.py` |
| 登出、強制登出或停用帳號 | 存取權杖與更新權杖立即失效；開著的主控台 30 秒內中斷 | `test_session_revocation.py`, `test_console_guard.py` |
| 已經換掉的更新權杖又被使用 | 整個工作階段撤銷，通知管理員與本人 | `test_session_revocation.py` |
| 用應用程式的資料庫帳號停用稽核表的保護或清空稽核表 | 資料庫拒絕 | `test_audit_hardening.py`, `scripts/sql/audit-harden.sql` |
| 加密備份被截斷、調換或修改 | 解密失敗，不會還原出被動過的資料 | `test_backup_encryption.py` |
| 對 127.0.0.1 或 169.254.169.254 的 IP 開主控台 | 被拒絕並說明原因 | `test_net_guard.py` |
| 主機名稱裡夾帶給模型的指令 | 提示詞把它標成資料並放在定界內，資料拆不掉定界 | `test_prompt_injection_framing.py` |
| 憑證代理要求別的憑證 | 回應不存在，沒有內容外流 | `test_cert_agents_api.py` |

右欄的測試在每次發版前執行；導入組織可以在自己的環境用同樣的情境驗收。
