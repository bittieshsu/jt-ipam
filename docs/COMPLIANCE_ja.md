## ISO/IEC 42001:2023：AI 機能と管理策

### AI 機能の一覧

| AI 機能 | 用途 | 既定 |
|---|---|---|
| AI チャット | 自然言語で IPAM を照会し、モデルはツールでデータを取得 | LLM を有効にすると利用可 |
| セマンティック検索 | 埋め込みモデルによる類似検索 | LLM を有効にすると利用可 |
| IP 調査の解説・IP トリアージカード | 収集済みの事実を説明にまとめる | LLM を有効にすると利用可 |
| ファイアウォールルール変更の解説 | プログラムが比較したルールの差分を解説 | LLM を有効にすると利用可 |
| IP 変更評価の AI 提案 | 評価結果から作業項目を提案 | LLM を有効にすると利用可 |
| AI 点検 | スケジュールでデータを確認し発見事項を一覧化 | 無効 |
| 外部 MCP | 外部の AI クライアントが jt-ipam のツールを呼び出す | 無効 |

モデルのエンドポイントは自前の Ollama か OpenAI 互換 API（管理者が選択）です。LLM が無効の間、上記の機能はモデルを呼び出しません。AI 点検と外部 MCP には個別のスイッチがあります。異常検出・ルール変更検出・IP 変更評価の結果はプログラムの照会で算出され、モデルが生成したものではありません。

## 導入組織が責任を持つこと

### 情報セキュリティ（ISO/IEC 27001:2022）

- アカウント：ユーザー管理ページの「ログインのセキュリティ」で 二要素認証を管理者必須または全員必須にし、例外を定期的に確認します。（A.5.17、A.8.5）
- 退職と異動：アカウントを無効化する（セッション・API トークン・開いているコンソールも同時に無効になります）か、「強制ログアウト」ですべてのログインを終了し、権限とグループのメンバーを調整します。（A.5.18、A.6.5）
- アクセスレビュー：権限の付与・グループのメンバー・API トークン・コンソール権限・ログイン中のセッションを定期的に見直し、必要に応じて監査ログと照合します。（A.5.18、A.8.2）
- 連携用アカウント：連携ごとに最小権限の専用アカウントを使い（多くは読み取り専用で十分）、パスワードとキーを定期的にローテーションし、期限の通知が届いたらトークンを交換します。（A.5.17、A.8.2）
- 鍵とバックアップ：バックアップの暗号化パスフレーズを設定し、jt-ipam のホスト以外に保管します。バックアップを外部に保存し、復号を含む復元訓練を定期的に行い、RPO と RTO を定めます。（A.5.30、A.8.13）
- 監査の証拠：監査ログを独立した書き換え不可の Graylog または SIEM のストレージへ転送し、チェーンの検証結果を定期的に確認します。バックアップの復元後や外部データベースを使う場合は harden-audit を実行します。（A.5.28、A.8.15）
- ネットワーク：必要な着信ポートだけを開け、jt-ipam を管理用ネットワークに置きます。Graylog DSV はできるだけ HTTPS を使い、平文の 8088 番が必要な場合は許可する送信元を制限します。（A.8.20、A.8.22）
- スキャンエージェントと証明書エージェント：必要なサブネットと証明書だけを割り当て、使わなくなったエージェントは無効化または削除し、エージェントのキーを定期的にローテーションします。（A.5.18）
- 更新：新しいバージョンを追い、CHANGELOG に沿ってアップグレードします（アップグレードスクリプトは先にバックアップします）。（A.8.8、A.8.32）
- マネジメントシステム：リスクアセスメントとリスク対応・適用宣言書・教育訓練・内部監査・マネジメントレビューは導入組織の責任です。（6.1.2、6.1.3、7.2、7.3、9.2、9.3）

### AI マネジメント（ISO/IEC 42001:2023）

- AI ポリシーと一覧：どの AI 機能を有効にし、誰が責任を持つかを決め、モデルのエンドポイントとバージョンを記録します。（5.2、A.2.2、A.3.2、A.4.2）
- データの流れ：自前のモデルか外部 API かを選びます。外部 MCP を開放すると、外部の AI クライアントが受け取ったデータがそのクラウドモデルに渡される可能性があるため、この流れは別途評価・承認します。（A.10.3）
- モデルの変更：モデルの切り替えやパラメーター変更の前に、固定の質問セットで回帰テストを行います（ツールの使い方・照会範囲・結果がないときの回答）。（A.6.2.4、A.6.2.5）
- 人によるレビュー：AI の回答と点検の発見事項は提案であり結論ではありません。ネットワークの変更は IP 変更評価とレビューの手順に従います。（A.9.2）
- 影響評価：誤った判断が人と組織に与える影響を評価します。例えば機器を誤ったユーザーに結び付ける、誤った保守の提案でサービスが停止する、などです。（6.1.4、8.4、A.5.2、A.5.4）
- インシデント対応：AI の誤りの報告手順と、AI 機能を一時停止する手順（LLM の全体スイッチ）を定めます。（A.3.3、A.8.4）
- マネジメントシステム：適用宣言書・教育訓練・内部監査・マネジメントレビューは導入組織の責任です。（6.1.3、7.2、7.3、9.2、9.3）

## 推奨する受け入れ確認

| 受け入れ確認 | 合格条件 | 確認方法（テスト・設定） |
|---|---|---|
| 組織 A と B が同じプライベートネットワークを使う | A は検索・IP の関連・AI チャット・MCP のいずれでも B のデータを取得できない | `test_search_overlapping.py`, `test_mcp_rbac_scope.py` |
| 読み取り専用トークンまたは一般アカウントが IP の変更を求める | サーバーが拒否し、データは変更されない | `test_api_token_scope.py`, `test_mcp_admin_tools.py` |
| 照会結果が 1 回の上限を超える | 総数と今回の件数を返し、一部の一覧を全体として扱わない | `test_mcp_tool_scoping.py` |
| データが見つからない | AI はその旨を伝え、アドレスや機器を作らない | `test_ai_no_results_are_explicit.py` |
| 承認後に根拠が変わる | 以前の承認はそのまま使えず、再評価が必要 | `test_change_impact_api.py` |
| API トークンの取り消しまたはアカウントの無効化 | 次の REST・API トークン・MCP のリクエストから拒否される | `test_api_token_scope.py`, `app/api/v1/dependencies.py` |
| 監査ログを変更または削除する | データベースが拒否し、末尾のアンカーで末尾の切り詰めを検出できる | `test_audit_immutability.py`, `test_audit_anchor.py` |
| コンソールのチケットを再利用する | 2 回目の使用は拒否される | `test_ticket_take_once.py` |
| 管理者が全員に二要素認証を必須にする | 未設定のユーザーはログイン時に設定してリカバリーコードを受け取り、自分で無効にできない。リカバリーコードは 1 回限り | `test_mfa_policy.py` |
| ログアウト・強制ログアウト・アカウントの無効化 | アクセストークンとリフレッシュトークンは即時に無効になり、開いているコンソールは 30 秒以内に切断される | `test_session_revocation.py`, `test_console_guard.py` |
| 入れ替え済みのリフレッシュトークンが再び使われる | セッション全体が取り消され、管理者と本人に通知される | `test_session_revocation.py` |
| アプリのデータベースアカウントで監査テーブルの保護を無効化または TRUNCATE する | データベースが拒否する | `test_audit_hardening.py`, `scripts/sql/audit-harden.sql` |
| 暗号化バックアップが切り詰め・入れ替え・改ざんされる | 復号に失敗し、改ざんされたデータは復元されない | `test_backup_encryption.py` |
| 127.0.0.1 または 169.254.169.254 の IP にコンソールを開く | 理由を示して拒否される | `test_net_guard.py` |
| ホスト名にモデル宛ての指示が含まれる | プロンプトはそれをデータとして区切りの中に入れ、データが区切りを閉じられない | `test_prompt_injection_framing.py` |
| 証明書エージェントが別の証明書を求める | 存在しないと応答し、内容は漏れない | `test_cert_agents_api.py` |

右欄のテストはリリースのたびに実行されます。導入組織は同じシナリオで自社環境の受け入れ確認ができます。
